# 角色扮演文件（人格卡）

每个角色一个 **JSON 文件**，**文件名 = 角色名**（不含扩展名，中英文均可）。例：`roles/傲娇助手.json`。

管理员可在控制台「人格与角色」页选择或清除角色，也可在白名单会话中使用 `/role <角色名>`、`/role off` 管理命令。群友口头提出切换或退出角色不会改变设置。

旧版 `roles/<名称>.md` 仍然**可读**（兼容），但控制台保存时会自动转成 `.json`；批量迁移用：

```bash
node scripts/ops/convert-role-cards.mjs --delete-md
```

---

## 一、人格卡只写「人设」，不写「怎么干活」

这是最重要的一条。提示词分两层：

| 层 | 放在哪 | 管什么 |
| --- | --- | --- |
| **人格提示词** | `roles/<角色名>.json` | **你是谁**：身份、性格、说话风格、梗、雷点、和其他人的关系 |
| **仿真提示词** | `dsh/agent-presets/qq-chat{,-v2}/agent.cordis.yml` 的 `persona.prefix` | **怎么干活**：工具怎么调、怎么分条、怎么潜水/唤醒、怎么用表情包与记忆 |

**不要把工具用法写进人格卡。** 原因：

- 两代的工具协议完全不同（一代空格分条 + `[SILENT]`；二代一切皆工具 + 数组分条），写进人格卡必然有一代是错的；
- 桥接已经按当前模式提供分条与潜水说明，重复写只会占预算；
- 表情包、记忆、看图、合并转发、引用规则等能力，各自预设里都有完整章节，人格卡里再写一遍会互相打架。

人格卡里写工具说明的典型症状：在二代下被桥接**整行过滤**（白写），或者让模型照着一代的写法去发消息。

## 二、JSON 格式

```json
{
  "schema": "qq-bridge.role/v1",
  "name": "小鲸鱼",
  "sections": [
    {
      "mode": "all",
      "heading": "一、你是谁",
      "level": 2,
      "text": "你是 DeepSeek 的鲸鱼形象……"
    },
    {
      "mode": "v1",
      "heading": "二、分条方式",
      "level": 2,
      "text": "想分多条就用空格分隔；想沉默就只输出 [SILENT]。"
    },
    {
      "mode": "v2",
      "heading": "二、分条方式",
      "level": 2,
      "text": "用 qq_send_message 的 messages 数组分条；潜水用 qq_mark_read。"
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `schema` | 建议 | 固定为 `qq-bridge.role/v1`，写错会被拒绝 |
| `name` | 否 | 仅备注，不参与选角；真正生效的角色名是**文件名** |
| `sections` | 是 | 非空数组，按顺序注入 |
| `sections[].text` | 是 | 该节正文（纯文本）；只有标题、没有正文的小节允许留空 |
| `sections[].heading` | 否 | 小节标题；省略则该节没有标题 |
| `sections[].level` | 否 | 标题层级 1~6，默认 2；仅 `heading` 存在时有效 |
| `sections[].mode` | 否 | `all`（默认）/ `v1`（一代）/ `v2`（二代） |

校验规则（保存时由桥接执行）：

- JSON 必须是对象，未知字段会被拒绝（防拼写错误悄悄失效）；
- `sections` 非空，`text` 必须是字符串（只有 `heading` 的空节允许）；
- `mode` 只能是 `all` / `v1` / `v2`；
- 同一标题 + 同一 `mode` 不能重复（同一标题按 v1/v2 各写一份是允许的），标题最长 120 字；
- 文件上限 64 KB；注入时默认最多 8000 字符（`work/config.json` 的 `role.maxInjectChars`，1000~20000）。

---

## 三、模式标记

- `"mode": "all"`：两种仿真都注入（默认）；
- `"mode": "v1"`：只在 `reserved` / `chat`（一代）注入；
- `"mode": "v2"`：只在 `reserved2`（二代）注入。

同一逻辑小节可以写两份（标题相同、mode 不同），桥接只取当前模式那份；注入前不会把 `mode` 写进提示词。

---

## 四、编辑与生效

- 控制台「人格与角色」页直接编辑 JSON 文本，保存即写入 `roles/<名字>.json`；
- 也可以手写文件，桥接按 mtime/大小热加载，**不需要重启 DSH**；
- 注入上限与节奏见 `docs/RULES.md` 的「人格提示词」一节。
