# 角色扮演文件（人格卡）

每个角色一个 Markdown 文件，**文件名 = 角色名**（不含扩展名，中英文均可）。例：`roles/傲娇助手.md`。

在群里对 QQ agent 说 `进入角色扮演：<角色名>`，或在控制台「人格与角色」页点选启用；说 `退出角色扮演` 恢复正常。控制台还可以设**默认人格**，并为单个群/私聊指定例外人格（保存即生效，群友改不了）。

---

## 一、人格卡只写「人设」，不写「怎么干活」

这是最重要的一条。提示词分两层：

| 层 | 放在哪 | 管什么 |
| --- | --- | --- |
| **人格提示词** | 本目录的 `roles/<角色名>.md` | **你是谁**：身份、性格、说话风格、梗、雷点、和其他人的关系 |
| **仿真提示词** | `dsh/agent-presets/qq-chat{,-v2,-v3}/agent.cordis.yml` 的 `persona.prefix` | **怎么干活**：工具怎么调、怎么分条、怎么潜水/唤醒、怎么用表情包与记忆 |

**不要把工具用法写进人格卡。** 原因：

- 两代的工具协议完全不同（一代空格分条 + `[SILENT]`；二代一切皆工具 + 数组分条），写进人格卡必然有一代是错的；
- 桥接已经在**每条消息**里告诉模型当前模式的分条方式与潜水方式，重复写只会占预算；
- 表情包、记忆、看图、合并转发、引用规则等能力，各自预设里都有完整章节，人格卡里再写一遍会互相打架。

人格卡里写工具说明的典型症状：在二代下被桥接**整行过滤**（白写），或者让模型照着一代的写法去发消息。

> **例外（人设层能管的频率）**：控制台「表情包参数 → 发送频率档位」选 **`完全根据人设来`** 时，
> 桥接不再给固定的「几轮一张」，而是让你按人格卡判断。这时可以在人格卡里写**表达习惯**而不是工具用法，
> 例如「发表情包：只在被戳中或想结束话题时来一张，平时不主动发」「斗图只接两轮」。
> 不要写「调用 qq_send_sticker」「每 3 轮发一张」这类机制/数字——机制归桥接，数字归档位；
> 写具体轮数会在档位切换后自相矛盾。其余档位下人设里的频率描述不生效（以档位为准）。
> 位置建议：放在「说话方式 / 节奏」那一节的末尾，写成一小块 `**表情包：…**`；
> 不要另开编号小节，否则后面各节的编号全要跟着改。
> 想让某几张表情专属于某个角色：把**角色名或别名写进表情备注**（如「角色名专属 …」），
> 每次唤醒会优先列出命中该角色的那几张（`buildStickerContext` 按人格排序，见 `src/sticker-lib.js`）。
> 备注跟角色名对不上时靠「公共子串 ≥3 字」兜底；要更精确就在 `STICKER_PERSONA_ALIASES` 里加一行别名。

## 二、需要区分模式时：在标题里加标记

同一个角色如果确实需要「一代这样说、二代那样说」，用**标题级模式标记**，桥接会只注入当前模式适用的小节：

```markdown
## 三、分条方式 〔一代〕
- 想分多条就用空格分隔；想沉默就只输出 [SILENT]。

## 三、分条方式 〔二代〕
- 用 qq_send_message 的 messages 数组分条；潜水用 qq_mark_read。

## 四、说话风格
- 这条没有标记 → 两种模式都会注入。
```

- 支持的写法：`〔二代〕`、`[v2]`、`（reserved2）`、`〔2 代〕`（一代同理：`〔一代〕`/`[v1]`/`（reserved）`）。
- 标记只是给桥接看的，**注入前会被去掉**，模型看到的标题是干净的。
- 没有标记的小节＝通用人设，两种模式都注入。
- 控制台打开某个人格时会显示「按模式注入：二代 N / 一代 M 字符」，并标出哪些小节会被跳过。

---

## 三、注入上限

- 默认**每条消息最多注入 8000 字符**（`config.json` 的 `role.maxInjectChars`，可设 1000~20000，控制台也能直接改；以控制台/`config.json` 当前值为准）。
- 截断发生在**按模式筛完小节之后**，所以另一代的专属内容不会占掉本次预算。
- 这是成本护栏：一代会把整张卡拼进每条提示词，8000 字符约合 5~8k token。
- 控制台的人格列表会标出「超出上限」与各模式的实际注入字符数。

> 建议把人格卡控制在 3000~5000 字符：够写清人设，也不至于让每条消息都背上很长的前缀。

### 二代的注入时机：不是每条消息都带

- **一代**：每次触发都把整张卡拼进提示词。
- **二代**：为了省 token，唤醒提示里只留一句「【当前角色】X（完整角色卡请调用 qq_get_prompt 查看）」，卡正文要靠 AI 自己调工具去取。
- 因此**改完卡 AI 未必知道**（它没有理由重读）。桥接现在按「名字 + mtime + size」记指纹：卡片一变，下一次唤醒就把整张卡推进去一次，之后照旧只给那一句。
- 改完卡想立刻确认：让 AI 调一次 `qq_get_prompt`，或直接跟它说「看一下你的人格卡」；重启桥接也会让指纹失效、下一条唤醒重新注入。

---

### 可选的「行为合同」小节

在卡片里加一个 `## 行为合同` 小节，桥接会把它逐行解析成结构化字段（格式 `- 键：值`）；与人设正文冲突时，它以**结构化字段**的方式被单独注入，比口号更硬：

| 键 | 作用 |
| --- | --- |
| `优先级` | 冲突时谁优先（例：`不主动`） |
| `被@` | 被 @ 时怎么反应 |
| `事实` | 需要模型始终记得的事实 |
| `认真` | 认真/低落时的语气 |
| `默认长度` | 默认回复长度 |
| `主动` | 主动开口的倾向；写「关闭」会让桥接不再按时给它「主动机会」 |
| `反驳主人` | **「人设自主」档**下，管理员要求它做事时按这个概率驳回一次（`15%` / `0.15` 都认；不写就用 `adminOps.vetoProbability`，默认 5%）。被驳回时桥接返回 `persona_veto`，模型按人设解释、不许重试 |
| `owner` / `熟人` / `常客` / `新人` / `陌生人` | 对不同关系的语气 |

## 四、推荐结构（模板）

```markdown
# 角色卡：<角色名>

## 一、你是谁
- 身份、自我认知、别人怎么称呼你、你的雷点。

## 二、说话风格
- 句子长短、口头禅、标点习惯、用不用 emoji/括号。
- 明确写「不要什么」通常比写「要什么」更有效（例如：不要总结、不要升华、不要客服腔）。

## 三、性格与反应
- 被夸/被怼/被无视时分别怎么反应；有没有嘴硬、摆烂、傲娇之类的固定模式。

## 四、梗与背景（可选）
- 你的来历、和群友的关系、常用梗、角色梗的边界。

## 五、回复示例（示范语气与长度）
- 几条「群友说 → 你回」的例子。
- 例子只示范**语气和长度**，不要在这里规定分条机制（那是仿真层的事）。
```

## 五、其它提示

- 想改性格直接改文件内容，控制台保存后**下一条消息即生效**（人格层由桥接每条消息注入，不用重启 DSH）。
- 只写人格、不写工具，换模式时不会出现「一代能用二代不能用」的规则。
- 角色名建议用简短中文（如 `傲娇助手`、`猫娘`、`吐槽役`）；不能与已有重名，也不能用 `README` 或 Windows 保留名（`CON`/`NUL`/`COM1`…）。
- 想临时关闭人格扮演，在控制台点「清除」；此时 AI 只按仿真提示词行动。
