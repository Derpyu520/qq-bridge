# 主动开口的概率：全局基础 + 每会话调整

控制台里有两个旋钮，**相乘关系没有，是相加后夹取**：

```text
某会话的主动概率 = clamp( 全局基础概率 + 该会话的主动概率调整, 0, 1 )
```

再乘上调度器的四道修正，才是这一次判定真正用的概率。

## 1. 全局基础概率

- 位置：控制台「二代仿真」→「主动机会参数」→ 触发概率
- 字段：`config.json` 的 `socialV2.proactive.probability`（0~1）
- 作用范围：**所有会话**（二代/三代共用同一个内核；三代页不重复显示这块）
- 同组的还有：检查间隔（默认 30~90 分钟）、安静阈值（默认 15 分钟）、总开关

> ⚠️ `socialV3.proactive` 是不生效的旧键：`effectiveSocialV3Config()` 不合并它，改它没有任何效果。

## 2. 每会话的调整值

- 位置：控制台「会话」页 → 每行「主动概率调整」，填 −100 ~ +100（单位 %）
- 字段：会话状态里的 `proactiveDelta`（−1~1），随 `state/social-v2.json` 持久化
- 缺省 0 = 完全跟随全局；负值可以把某个群调得比全局更安静
- 只允许控制台 / 管理员改：`POST /api/socialV2/proactive { key, delta }` 会拒绝任何带
  `x-agent-token` 的调用，模型不能给自己调频率

例子：全局 40%，

| 会话 | 调整 | 最终基础 |
| --- | --- | --- |
| 主群 | +20% | 60% |
| 工作群 | −30% | 10% |
| 其他群 | 0 | 40% |

## 3. 还有四道修正

命中顺序（都乘在上面算出的概率上）：

| 条件 | 系数 |
| --- | --- |
| 有待说想法（`qq_memory_append` 的 pendingThought） | ×1.4 |
| 30 分钟内刚回过话 | ×0.5 |
| 本地时间 23:00–08:00 | ×0.3 |
| 一小时内自己已发 ≥5 条 | ×0.3 |

此外还要求：会话安静时长 ≥ 安静阈值、会话不处于忙碌回合。任何一条不满足都不会冒泡。

## 4. 怎么看它为什么没冒泡

每轮判定都会写一行日志（`state/bridge.log`）：

```text
[reserved3] 主动判定 group:123: 基础40% + 本会话+20% = 60%；夜间×0.3 → 18%；安静 12/15min → 跳过
```

看这一行就知道是概率不够、被修正压掉，还是群根本没安静够。

## 5. 优先级与总闸

从上到下依次覆盖：

1. `/mute`（会话静音）：彻底不唤醒，主动检查也不排
2. 人格卡「行为合同」的 `- 主动：关闭`：该会话不排主动检查
3. 全局 `proactive.enabled=false`：全部会话都不排
4. 概率 = 全局 + 本会话调整（本文档）

> 静音和切人格都会先把该会话的排程清掉。恢复唤醒 / 人格切换完成后会**重新排程**
> （`scheduleProactiveCheckV2`），否则这个会话会一直"没有主动机会"，直到下次重启。
> 2026-10-26 的真实故障就是切人格把排程清了没补：私聊设了 +80%，三个多小时一次判定都没跑。

- `src/bridge.js`：`scheduleProactiveCheckV2()` 里读 `st.proactiveDelta` 并写判定日志
- `public/console.html`：会话表的「主动概率调整」列
- `scripts/test-proactive-session.mjs`：接口级回归（读写、夹取、拒绝模型调用、落盘）
- `scripts/test-proactive-rearm.mjs`：切人格 / 静音恢复后必须重新排程
