# docs

qq-bridge's documentation, as a browsable HTML site (tabs, sidebar,
breadcrumbs, on-this-page TOC, search, dark mode). Pure Python stdlib — no
`pip` / `npm`, no external build tool. Open `docs/index.html` or run the
preview server.

## Preview

```bash
./docs/run_dev.sh          # live-reload preview, http://0.0.0.0:8002/
./docs/run_dev.sh 9000     # custom port
```

## Layout

```text
docs/
├── index.html              # home: entry points for each kind of reader
├── pages/
│   ├── use/                # tab 使用指南 — for people who run the bot; flat
│   ├── dev/                # tab Developer Guide — for people who change or review the code
│   │   ├── core/           #   the spine: blueprint · architecture · codebase-map · glossary
│   │   ├── design-docs/    #   one page per mechanism in src/
│   │   ├── security/       #   threat model · baseline · privacy scan · release checks · reporting
│   │   ├── contributing/   #   setup · testing · pull requests · DSH upgrade checklist
│   │   └── tmp/            #   discussion / proposal pages — gitignored, local dev server only
│   └── records/            # tab 记录 — dated, frozen once written
│       ├── adaptation/     #   DSH version adaptation records
│       └── reviews/        #   reviews of the repo on a given day
├── 404.html
├── _lib/  assets/          # site engine (copied from htmlkb, see below)
├── _site.json  run_dev.sh
└── README.md               # this file
```

Which tab a page belongs to: does someone who runs the bot need it without
touching the code (→ `use/`)? Is it only needed when changing or reviewing the
code (→ `dev/`)? Does it record the state at one date or version and stop being
updated (→ `records/`)? Current conclusions inside a record are lifted into
`use/` or `dev/`.

## Editing

Every page is hand-maintained HTML. Edit only the content inside
`<main class="doc-body">`; everything around it (header, breadcrumbs,
right-hand TOC) and the two indices the browser draws the sidebar and search
from (`assets/nav.json`, `assets/search-index.json`) are regenerated by

```bash
python3 docs/_lib/_wrap_handwritten.py
```

While `./docs/run_dev.sh` runs it does this on every change, including added
or removed pages. Commit `nav.json` and `search-index.json` with the pages.

Private pages: anything gitignored under `pages/` (here `pages/dev/tmp/`) is
left out of the committed indices and listed only in the `assets/*.local.json`
twins, which the dev server serves and git ignores. A tmp page is named
`MM-DD · Title` (`<title>`, `<h1>` and `<meta name="nav-title">`), keeps its
own styles scoped to a wrapper class, and its stem goes to the front of the tmp
section's `order` in `pages/dev/_tab.json`.

The dev server also has a settings panel (⚙, LAN password off by default) and
in-browser editing (✏️); see htmlkb's "Dev-server features" recipe. Its
settings file `.site.json` is gitignored.

To add a page: create `pages/<tab>/<section>/<slug>.html` with a `<title>` and
a `<main class="doc-body">` block, add the slug to that section's `order` in
`pages/<tab>/_tab.json`, then run the wrap step. A new tab is a new folder
under `pages/` with its own `_tab.json`.

Linking: between pages use relative `.html` links. Links into the repo
(code, `LICENSE`, …) use full GitHub URLs
(`https://github.com/Derpyu520/qq-bridge/blob/main/...`).

The repo-root Markdown files (README, RULES, NOTICE, SECURITY, CONTRIBUTING,
roles/README) are still in place. Since the 2026-11-03 reorganisation their
content also lives, split up, in the site pages, and the two copies are not
synchronised; whether the root files are trimmed or mirrored again is an open
decision.

## 公开与本地文档边界

（moved here from the former FOLDER_MAP § 三 and the former docs index, 2026-11-03）

以下目录或文件可能存在于维护者的本地工作副本，但被 `.gitignore` 排除，**不属于公开仓库文档**：

- `docs/audits/`、`docs/design/`、`docs/legacy/`、`docs/research/`；
- `docs/guides/PROJECT_GUIDE.md`、`docs/guides/VOICE.md`。

这些资料只用于本地追溯，可能包含旧配置、旧实现或个人信息。公开文档不要给这些本地资料提供链接。
`PROJECT_GUIDE.md` 是历史说明书，不是当前实现的唯一权威来源；当前行为以代码、入库指南和带日期的验证记录为准。
本地索引如需保留这些条目，应使用纯文本说明，不要给公开读者提供无效链接。

根目录主要保留 `README.md`、`README.en.md`、`RULES.md`。`LICENSE`、`NOTICE.md`、`SECURITY.md`、
`CONTRIBUTING.md` 及 `.github/` 社区健康文件是约定例外，不适用于“其他文档一律进 `docs/`”的规则。

## History

- Until 2026-11-03 the docs in this folder were Markdown (`docs/README.md`,
  `docs/FOLDER_MAP.md`, `docs/guides/*.md`). They were converted to HTML once
  with a one-off Markdown → HTML converter and the Markdown was removed; the
  old files are in git history.
- The content was then moved, verbatim, into the `use/` · `dev/` · `records/`
  layout. Every moved block carries a
  `<!-- moved verbatim from <source> [<section>] -->` comment, so each page can
  later be revised against the code section by section.

### Local changes to the template engine

Only the three site-config tables in `_lib/_wrap_handwritten.py` differ from
the template:

- `HANDWRITTEN`: the root landing, plus accent classes for the Core pages
  (blueprint · architecture · codebase-map · glossary).
- `SECTION_CLASS_BY_PREFIX`: accents for design-docs, security, the rest of
  `dev/`, and `records/`.
- `DIR_LABEL_OVERRIDES`: display labels for the tab and section folders
  (`use`, `dev`, `records`, `core`, `design-docs`, `security`, `contributing`,
  `adaptation`, `reviews`, `tmp`) so the breadcrumbs read right.

When pulling a newer engine from htmlkb, copy every other file over and keep
these three tables.
