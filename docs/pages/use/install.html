安装与首次运行

快速开始

准备好 Windows 10 / 11、Node.js ≥ 22.13，以及以下两个独立运行的服务：

  • DSH Web：当前有 0.2.0-rc.2 / 0.2.1-rc.2 的验证记录，其他版本见兼容范围。
  • SnowLuma：请自行按上游文档安装、启动并登录，开启 OneBot WebSocket 服务端和 HTTP API。

1. 获取项目

在 PowerShell 中运行：

git clone https://github.com/Derpyu520/qq-bridge.git
cd qq-bridge
npm install
Copy-Item config.example.json config.json

默认分支 main 为正式发布线；dev 用于开发与测试。

3. 安装 DSH 插件

node scripts/setup-dsh.mjs

这一步会把聊天预设和 MCP 工具接入 DSH，首次安装也必须执行。完成后重启 DSH；使用非 web profile 时见安装指南。

4. 启动并测试

npm start

打开 本地控制台 并输入控制台令牌。自动生成的令牌保存在 state/console-token；如果已在 config.json 配置 consoleToken，则使用该值。启动日志不会打印令牌。新装默认使用二代仿真模式（reserved2），会选择性发言；测试收发时可先切到 chat，再从白名单会话发送消息。

Windows 也可双击 start.bat 以守护模式运行，关闭窗口即停止。

qq-bridge 仓库本身包含桥接、控制台和插件，但 DSH 端的两个聊天模式（qq-chat / qq-chat-v2）以及 MCP 挂载 不在仓库根目录，需要通过本说明安装到目标设备的 DSH 环境中。

上游行为标注：本文中的 [Hook]、进程枚举、PID/pipe 等均为 SnowLuma 接入日志字段；qq-bridge 不注入、不挂钩、不修改 SnowLuma 本体。

兼容范围

桌面版端口自动发现默认开启。多实例或固定端点部署可将 config.json 的 dsh.autoDiscoverPort 设为 false，此时桥接只使用配置的地址，不扫描或重绑其他实例。

协议代际与预设 schema 必须分别匹配，不能只凭斜杠 RPC 判断可用性（#9）。

DSH 版本处理方式
0.1.1-rc.2 及更早历史标签 v0.1.0；当前分支不支持旧点号协议
0.1.2-alpha.1历史标签 v0.1.2-alpha.1 使用 persona.text；当前分支不兼容该 schema
0.1.2 的其他版本～0.1.4当前预设不支持；没有逐版本验证的标签映射，建议升级到已验证版本
0.1.5-rc.1 / 0.1.7-rc.2分别使用历史标签 v0.1.5 / v0.1.7
0.2.0-rc.2 / 0.2.1-rc.2当前版本已有适配与验证记录

历史标签不包含后续安全修复。DSH 0.2.1-rc.3 的个别环境反馈仍需对应安装形态复现， 不能把某个环境成功或失败的结果推广到全部安装。

安装步骤

在目标设备上：

  1. 克隆/获取仓库：

    git clone https://github.com/Derpyu520/qq-bridge.git
cd qq-bridge

    默认分支 main 是正式发布线，具体版本以 Releases 为准，clone 下来无需切换分支。 dev 是开发与测试线，不保证稳定；只在想参与开发或测试未发布改动时才切过去。

  1. 安装依赖：

    npm install

    postinstall 会自动修补 @snowluma/sdk 的 ESM 打包 bug。

  1. 创建配置文件：

    cp config.example.json config.json

    Windows CMD 用户请用：copy config.example.json config.json

    然后编辑 config.json，填写：

    • snowluma.wsUrl / httpUrl（例如 ws://127.0.0.1:3001 / http://127.0.0.1:3000，分别对应 OneBot WebSocket 与 HTTP API 端口）
    • snowluma.accessToken
    • dsh.authToken（通常留空：桥接优先使用本机 DSH 持久化签名密钥生成会话 Cookie，不依赖 guard 日志；旧启动日志仅作为兼容兜底）
    • ownerQQ
    • allow.private / allow.groups

  1. 运行 DSH 端安装脚本：

    node scripts/setup-dsh.mjs

    默认安装到 web profile；如果 DSH 使用其他 profile，可以传参：

    node scripts/setup-dsh.mjs <profile名>

    脚本会完成：

    • 安装 agent preset：通过 plugins/qq-agent-presets 这个 DSH bundle 把 qq-chat / qq-chat-v2 两条 @deepseek-ai/dsh-agent-preset 行插入 profile（DSH 0.1.7 起 preset 不再是 ~/.dsh/.agent-presets/<名>/ 目录，该目录完全不被读取）。patch 由 scripts/build-agent-preset-patches.mjs 从 dsh/agent-presets/ 的权威源生成
    • 在 ~/.dsh/profiles/web/cordis.patch.yml 挂载：
      • mcp-snowluma（src/mcp-snowluma-safe.js，带 toolCallTimeoutMs: 725000）
      • mcp-snowluma-host（src/mcp-host-server.js）
      • mcp-web-search-safe（src/mcp-web-search-safe.js）
    • 在 ~/.dsh/profiles/web/package.json 注册 qq-mode-console 与 qq-agent-presets（dsh.profile.bundles + link: 依赖），并维护 node_modules 下的 junction
    • 把 qq-mode 的默认模式设为 reserved2（二代仿真）
    • 创建本地 state/mode.json（mode: reserved2）作为 DSH settings 不可用时的兜底
    • 尝试自动执行 dsh plugin --profile web install（当 dsh CLI 在 PATH 中可用时），注册两个插件的 bundle 依赖；若 dsh 不在 PATH，缺失依赖时 DSH 会提示补跑

    脚本可重复运行（幂等）：它会重建 qq-agent-presets 的 preset patch、更新 MCP 路径并重建失效的插件链接。 MCP 条目通过 YAML 解析后按顶层 insert 内的条目 id 增删（不依赖标记注释），支持带引号的 id、共享 insert 与行内 YAML，并保留其他插件配置和嵌套数据。 脚本在写入前验证 YAML；无法解析时停止，不覆盖配置或 preset。只修复历史版本在文件开头遗留的多余 []，不会删除正文中的空数组或文本。 YAML 格式与注释会在序列化时规范化；每次实际改动内容前，完整原文会保存在同目录的 cordis.patch.yml.bak-<ISO 时间戳>（例如 cordis.patch.yml.bak-2026-10-31T13-10-31-123Z），只保留最近 5 份；内容无需改动时不会新增备份。 可用 node scripts/test-audit-setup.mjs 验证幂等性、配置保留、路径边界和 Windows CLI 调用；测试只使用独立的临时仓库和 DSH_HOME，不启动真实 DSH。 已存在的 qq-bridge/state/mode.json 会被保留（不覆盖用户设置）；全新安装才会写入 mode: reserved2。 如果之后把 qq-bridge 目录移动/重新 clone 到别的路径，请重新运行一次本脚本，否则 DSH 里的 MCP/插件绝对路径会指向旧位置。 也可用环境变量指定 DSH 根目录：DSH_HOME=/path/to/.dsh node scripts/setup-dsh.mjs <profile>。 <profile> 必须是单个目录名，不能包含路径分隔符或 .. 路径跳转。离线准备配置时，可设置 QQ_BRIDGE_SKIP_DSH_INSTALL=1 跳过自动安装 bundle，随后手动运行 dsh plugin --profile <profile> install。 Windows 下脚本通过隐藏的 cmd.exe 调用 npm 的 dsh.cmd 启动器；DSH_HOME 和 profile 参数会传给该进程。

  1. 重启 DSH：

    必须重启 DSH（或让 DSH 重新加载 profile），新 preset 和 MCP 工具才会生效。

    默认模式为 reserved2（二代仿真），即“文本不自动转发、AI 通过工具自主收发”。如果你想改用 chat / closed-agent / reserved，在桥接控制台（默认 http://127.0.0.1:3100）顶部按钮切换即可 —— 桥接会同时写入 DSH 设置与本地 state/mode.json，无需重启（每 5 秒轮询即时生效）。本地文件保存模式兜底与 closedAgentPreset；正常情况下模式以 DSH 设置为准，请通过控制台切换。

验证是否装好

离线安全回归：node scripts/test-audit-setup.mjs 与 node scripts/test-audit-setup-guards.mjs。后者直接执行两套 preset 的限制插件，验证本地工具、未声明工具与裸 web_fetch / web_search 被拒绝，而带 SSRF 防护的 mcp__web-search-safe__* 仍然可用。更新 preset 后需重新运行安装脚本并重启 DSH，现有 DSH 安装中的旧副本才会更新。

  1. 一键自检：npm run verify:adaptation —— 覆盖 preset persona schema、bundle patch 与工具守卫、版本身份一致性、preset fail-closed 护栏，以及运行中 DSH 的协议与活体回合（qq-mode、session/projections、session/control、stopSessionWork、$events、session/modelCatalog 等）。具体断言数量以脚本输出为准。

    若你的环境禁止起子进程（例如在 DSH 的沙箱会话里跑），脚本内那批 node --check 语法检查会被显式记为跳过（⏭）而不是报假失败 —— 请在普通终端重跑以覆盖它们。

  2. 切换桥接模式：打开桥接控制台（默认 http://127.0.0.1:3100），顶部的「聊天模式 / 封闭 Agent / 一代仿真模式 / 二代仿真模式」按钮即为当前生效的切换入口。控制台会同时写入 DSH 设置与本地 state/mode.json。

    ℹ️ DSH 设置页 Plugins → Plugin configuration 里不会出现 qq-mode 卡片：该槽位要求插件自带浏览器半（package.json 的 dsh.client + lib/client.js），而 plugins/qq-mode-console 只实现了 host 半。qq-mode 命名空间本身可用（settings/describe 能列出、settings/update 能写成功），缺的只是那张 GUI 表单 —— 所以模式改走控制台。参见下方「常见问题」。 DSH 0.2.0 起命名空间不再需要任何注册调用：它由 profile 里 id: qq-mode 那条 loader entry + 插件导出的 Config（带 volatile 字段）推导出来。0.1.x 的 ctx.settings.register() 已被 DSH 删除。

  3. 新建会话时：agent preset 列表中应能看到：
    • QQ 聊天角色（qq-chat）
    • QQ 聊天角色（二代仿真）（qq-chat-v2）
  4. 工具列表：QQ 会话中应能看到 mcp__snowluma__*、mcp__snowluma-host__*、mcp__web-search-safe__* 等工具；不应看到 dev_* 等开发工具。
