2.2 @snowluma/sdk 与 @snowluma/mcp 的许可状态

核验事实（2026-09-20，可自行复核）：

  1. 两个包的 package.json 均声明 "license": "SEE LICENSE IN LICENSE"；
  2. 发布的 npm 包内不含 LICENSE 文件：npm pack @snowluma/sdk --dry-run 的文件清单仅有 dist/、README.md、CHANGELOG.md、VERSIONING.md；
  3. 成因在源仓库：packages/sdk/package.json 与 packages/mcp/package.json 的 files 字段 未包含 LICENSE，且 packages/sdk/LICENSE、packages/mcp/LICENSE 均不存在。

认定：上述两个包的许可状态在包内不可判定，SEE LICENSE IN LICENSE 指向的文件并不存在。 但 SnowLuma LICENSE §1 对 "Software" 的定义为「the SnowLuma source code and assets in this repository」，而 packages/sdk、packages/mcp 位于该仓库之内，故二者受同一非商业许可约束。 此为 §1 定义的直接结论。

本软件的处理：

  1. 仓库内不含、不分发上述两个包的代码。node_modules/ 已在 .gitignore 中；已跟踪文件内不包含 任何原生二进制（.node / .dll / .so），亦不包含 @snowluma 路径下的文件。
  2. npm install 的 postinstall 会运行 scripts/patch-snowluma-sdk.mjs，对 node_modules/@snowluma/{sdk,mcp} 的 dist/**/*.js 执行一次机械修补（为相对导入补充 .js 扩展名，规避该两包自身的 ESM 打包缺陷）。该修补仅作用于本机安装副本，不进入本仓库； SnowLuma 许可 §2(c) 允许为自身非商业使用而修改。本软件不修改 SnowLuma 应用本体， 上述说明仅指对本机 npm 安装副本进行兼容性修补。
  3. 后续如替换这些依赖，需同步调整客户端实现与 postinstall 修补，避免留下失效的构建步骤。 @snowluma/mcp 的 catalog.js 快照属于再分发其内容，不得提交至本仓库； 仓库根目录曾跟踪的 _snowluma-catalog.json 已删除并加入 .gitignore。
  4. 如需消除上述不确定性，应向 SnowLumaDevs 书面确认 packages/sdk 与 packages/mcp 所适用的许可。

三、与 SnowLuma 的关系

3.1 独立关系声明

qq-bridge 是独立维护的第三方工具，不是 SnowLuma 的子项目；qq-bridge 与 SnowLuma、DeepSeek、 腾讯 / QQ 之间不存在隶属、官方合作或背书关系。

3.2 互操作性质

本软件不在仓库内包含或分发 SnowLuma 的源码与二进制，仅通过 OneBot v11 协议与其通信。 它会在本机读取安装目录下的 config/onebot_*.json，从已有账号配置中寻找当前可用的接入令牌， 并只将令牌用于连接相应的 OneBot 地址。本软件不是 SnowLuma 的修改版或衍生版本。

3.4 关于 §4(b) 的解释与不确定性

本软件注意到该条存在两种解释：

  • 一种解释认为，§4(b) 紧接商业限制，且 §1 已将基于本软件的付费托管、部署、代搭列为商业用途， 故其意旨在于禁止将商业使用包装为周边项目以规避 §4(a)，而非禁止一切互操作工具。
  • 另一种解释更为严格，且更具文本依据：§4(a) 已表述为「Commercial Use of the Software in any form is PROHIBITED」，若采用前一种解释，§4(b) 将不具独立适用范围，与同一许可内部应作一致 解释的原则相悖。赋予 §4(b) 独立含义的正是字面解释：它是一项不含商业限定语的独立禁止。

此外，§2 授予的权利为可撤销（revocable），EULA §8 允许著作权人单方面更新条款。

本软件的立场：不因协议互操作而假定获得额外授权。使用者在评估公开分发、托管或相关服务时， 应自行核对 SnowLuma 条款，并在需要时联系 SnowLumaDevs 确认；本软件不声称已取得额外许可。

EULA §5.4（以中文文本为准）：「除事先取得著作权人的书面授权外，您仅可为 LICENSE 允许的 非商业用途，以专有组件随本软件提供的形式运行该组件；不得复制、修改、单独再分发或再许可该组件。 将其并入第三方安装包或 Docker 镜像、通过自动化脚本部署，或者将其用于任何商业用途， 均须事先取得书面授权。」

据此，本软件不安装、不复制、不打包、不自动部署 SnowLuma 及其原生组件，亦不以程序化方式启动或 结束其进程；仅进行端口探测与状态查询，缺失时提示使用者自行经官方渠道获取并启动。

该约束已作为设计不变量 L6 记录于本项目的安全基线。 原 start_snowluma / stop_snowluma 工具与 snowluma.allowProcessControl 配置项已于 v0.1.5 移除， 并有回归断言（scripts/test-audit-setup-guards.mjs）防止回退。

五、使用风险与免责

  1. 使用非官方协议工具接入第三方平台，可能违反该平台的服务条款并导致账号受限，风险由使用者承担。
  2. 本软件将聊天内容交由第三方大语言模型处理，并可能代账号发言。部署方应仅在 RULES.md 所述白名单与审计机制下运行，不应在未配置白名单的情况下向任意群聊或 陌生人开放。
  3. 部署方应保护控制台令牌、config.json 与 state/ 的访问权限，不应将 DSH 或本软件的端口 暴露于公网。
  4. 本软件按「现状」提供，不附带任何明示或默示担保。在适用法律允许的最大范围内，著作权人 不对使用本软件所产生的任何后果承担责任。此条与 LICENSE 的 No Liability 条款一致。

使用边界与许可

  • 仅在知情并获准的会话中使用，遵守平台规则；使用非官方 QQ 后端可能导致账号受限。
  • 聊天内容会经 DSH 发送给所配置的模型服务；黑话自动研究默认开启，可能将提取的关键词发送给搜索服务。数据流与关闭方式见 NOTICE。
  • 保护 config.json、state/ 与控制台令牌，保持服务仅在本机可访问。
  • DSH 离线期间的消息队列仅保存在内存中，每个会话最多 50 条；桥接进程退出后队列丢失，不保证送达。
  • 本工具不实现 QQ 登录或底层协议，不安装、打包或启停 SnowLuma 后端；当前客户端仍依赖 @snowluma/sdk 等包，第三方组件适用各自条款。
