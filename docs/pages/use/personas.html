人格卡

提示词的两层边界（仿真 vs 人格）

二代仿真模式下，AI 拿到的提示词由两层拼成，控制台「人格与角色」页可分别查看与修改：

层位置管什么生效方式
仿真提示词（两代各一份）dsh/agent-presets/qq-chat/agent.cordis.yml（一代）与 qq-chat-v2/agent.cordis.yml（二代）的 persona.prefix怎么调工具、怎么参与群聊（行为与协议：安全规则、工具协议、唤醒/分条/记忆/黑话等）控制台可按代次分别编辑；保存会写仓库源文件并同步到 ~/.dsh/plugins/qq-agent-presets/presets/<preset>.patch.yml（旧安装的 .agent-presets 目录仅作兼容回退）；新会话自动用新版，正在进行的 QQ 会话需 POST /api/session/reset 或重启 DSH
人格提示词roles/<人格名>.mdAI 是谁、什么性格、怎么说话（人设与语气）桥接按当前模式与注入节奏提供，保存后的下一次唤醒生效
  • 拼装顺序：仿真提示词 → 人格提示词 → 本轮消息。
  • 人格卡只写人设，不写工具用法：两代工具协议不同（一代空格分条 / [SILENT]，二代一切皆工具），写进人格卡必然有一代是错的；桥接已经按当前模式提供分条与潜水说明。写作规范见 roles/README.md。
  • 同一个角色确实需要分代时，用标题级模式标记：## 分条方式 〔一代〕 / ## 表情包 〔二代〕；无标记的小节两代都注入，标记在注入前会被去掉。桥接按当前模式筛完小节再截断。
  • 注入上限：完整人格卡单次最多注入 8000 字符（config.json 的 role.maxInjectChars，1000~20000，控制台可改）。这是成本护栏。
  • 注入节奏：首次唤醒 / 角色卡文件变化 / DSH 会话重建（/reset、换模式、换 preset、DSH 重启）时注入完整人格卡，其后每 role.injectEveryNWakes 次唤醒（默认 4，设 1 = 每次都全量）再全量一次，其余唤醒只给一行「角色卡已给过」的提醒。计数按 QQ 会话存在 state/role-inject.json，签名里带当前 DSH sessionId —— 新会话的上下文是空的，必须重新全量。
  • 仿真提示词保存前会做硬性校验：保留 你没有本地工具 / 群友没有管理权限 / API 令牌 / 角色由桥接注入 / 不会自动发送到 QQ 这些安全不变量，且正文 ≥ 500 字符；缺失即拒绝保存（否则会同时削弱权限边界并让 npm run test:audit 变红）。写入前自动备份到 state/preset-backups/，可一键还原；还原时同样校验。
  • 一代遗留写法（空格分句、[SILENT]、自动转发）若出现在未标记的小节里，二代下会被兜底整行过滤；控制台会提示把它们移到 〔一代〕 小节。
  • 两层提示词都只能由控制台（管理员令牌）修改：带 x-agent-token 的请求对这些端点一律 403，QQ 群里的 AI 无法改写自己的提示词。

每个角色一个 Markdown 文件，文件名 = 角色名（不含扩展名，中英文均可）。例：roles/傲娇助手.md。

管理员可在控制台「人格与角色」页选择或清除角色，也可在白名单会话中使用 /role <角色名>、/role off 管理命令。群友口头提出切换或退出角色不会改变设置。

一、人格卡只写「人设」，不写「怎么干活」

这是最重要的一条。提示词分两层：

层放在哪管什么
人格提示词本目录的 roles/<角色名>.md你是谁：身份、性格、说话风格、梗、雷点、和其他人的关系
仿真提示词dsh/agent-presets/qq-chat{,-v2}/agent.cordis.yml 的 persona.prefix怎么干活：工具怎么调、怎么分条、怎么潜水/唤醒、怎么用表情包与记忆

不要把工具用法写进人格卡。 原因：

  • 两代的工具协议完全不同（一代空格分条 + [SILENT]；二代一切皆工具 + 数组分条），写进人格卡必然有一代是错的；
  • 桥接已经按当前模式提供分条与潜水说明，重复写只会占预算；
  • 表情包、记忆、看图、合并转发、引用规则等能力，各自预设里都有完整章节，人格卡里再写一遍会互相打架。

人格卡里写工具说明的典型症状：在二代下被桥接整行过滤（白写），或者让模型照着一代的写法去发消息。

二、需要区分模式时：在标题里加标记

同一个角色如果确实需要「一代这样说、二代那样说」，用标题级模式标记，桥接会只注入当前模式适用的小节：

## 三、分条方式 〔一代〕
- 想分多条就用空格分隔；想沉默就只输出 [SILENT]。

## 三、分条方式 〔二代〕
- 用 qq_send_message 的 messages 数组分条；潜水用 qq_mark_read。

## 四、说话风格
- 这条没有标记 → 两种模式都会注入。
  • 支持的写法：〔二代〕、[v2]、（reserved2）、〔2 代〕（一代同理：〔一代〕/[v1]/（reserved））。
  • 标记只是给桥接看的，注入前会被去掉，模型看到的标题是干净的。
  • 没有标记的小节＝通用人设，两种模式都注入。
  • 控制台打开某个人格时会显示「按模式注入：二代 N / 一代 M 字符」，并标出哪些小节会被跳过。

三、注入上限

  • 完整人格卡单次最多注入 8000 字符（config.json 的 role.maxInjectChars，可设 1000~20000，控制台也能直接改）。
  • 截断发生在按模式筛完小节之后，所以另一代的专属内容不会占掉本次预算。
  • 这是成本护栏。完整人格卡按注入节奏发送，不是每次唤醒都发送；8000 字符约合 6~8k token，实际消耗取决于模型。
  • 控制台的人格列表会标出「超出上限」与各模式的实际注入字符数。

建议把人格卡控制在 3000~5000 字符：够写清人设，也能控制完整注入时的上下文开销。

四、推荐结构（模板）

# 角色卡：<角色名>

## 一、你是谁
- 身份、自我认知、别人怎么称呼你、你的雷点。

## 二、说话风格
- 句子长短、口头禅、标点习惯、用不用 emoji/括号。
- 明确写「不要什么」通常比写「要什么」更有效（例如：不要总结、不要升华、不要客服腔）。

## 三、性格与反应
- 被夸/被怼/被无视时分别怎么反应；有没有嘴硬、摆烂、傲娇之类的固定模式。

## 四、梗与背景（可选）
- 你的来历、和群友的关系、常用梗、角色梗的边界。

## 五、回复示例（示范语气与长度）
- 几条「群友说 → 你回」的例子。
- 例子只示范**语气和长度**，不要在这里规定分条机制（那是仿真层的事）。

五、其它提示

  • 想改性格直接改文件内容，控制台保存后下一次唤醒即生效，不用重启 DSH。人格层按当前模式与注入节奏提供；变化后会重新完整注入。
  • 只写人格、不写工具，换模式时不会出现「一代能用二代不能用」的规则。
  • 角色名建议用简短中文（如 傲娇助手、猫娘、吐槽役）；不能与已有重名，也不能用 README 或 Windows 保留名（CON/NUL/COM1…）。
  • 想临时关闭人格扮演，在控制台点「清除」；此时 AI 只按仿真提示词行动。
