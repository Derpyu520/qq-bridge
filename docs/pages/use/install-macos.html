macOS 安装

本页记录在 macOS（Apple Silicon）上实测跑通的装法。通用部分（兼容范围、setup-dsh.mjs 做了什么、验证步骤）见安装与首次运行，这里只写 macOS 上不一样的地方。

支持级别：macOS 有实测运行记录，但不在测试矩阵内。SnowLuma 上游列出的平台是 Windows / Linux，macOS 不在其中；下面 SnowLuma 跑在 Docker 的 Linux 环境里，属于上游未覆盖的用法。

验证环境

组件实测版本说明

DSH桌面版 0.2.1-rc.2用 dsh web 提供 Web 接口
SnowLuma上游 Docker 镜像 v2.1.1跑在 Colima（aarch64，runtime docker）里；Docker Desktop / OrbStack 未实测
qq-bridge0.2.1-r2main 分支

和 Windows 的差异

  • 没有 start.bat / restart.bat：用 npm start 前台运行，没有守护进程，退出后不会自动重启。
  • DSH 端口不会自动发现：端口枚举目前只有 Windows 实现（netstat + tasklist）。macOS 上桥接只会尝试 config.json 的 dsh.baseUrl 和环境变量 DSH_WEB_URL，必须手动填对。
  • state/ 权限：用 chmod 收紧为仅本用户可读写，不涉及 Windows ACL，不需要管理员权限。
  • setup-dsh.mjs：插件链接建成普通目录 symlink（Windows 上是 junction），并直接调用 PATH 里的 dsh 命令。

1. 准备工具

brew install node@22 git
# 可选：语音功能需要 ffmpeg
brew install ffmpeg

node@22 是 keg-only，按 Homebrew 安装结束时的提示把它加进 PATH，然后确认 node -v ≥ 22.13。

2. SnowLuma

qq-bridge 不安装、不打包、不启停 SnowLuma（设计不变量 L6，见 许可与边界），本仓库也不提供启动它的命令或脚本。请自行完成：

  1. 准备一个 Docker 运行时。以下任选其一，它们都提供同样的 docker 命令，后续步骤不受影响：
    • Colima（实测使用）：免费开源，纯命令行。 
      brew install colima docker
colima start
    • Docker Desktop：Docker 官方的图形界面版，用户最多。较大的公司需要付费订阅，个人与小团队免费。
    • OrbStack：启动快、占用资源少，个人免费、商用收费。
  2. 按 SnowLuma 官方 Docker 部署文档部署上游镜像（提供 linux/arm64），并按文档登录 QQ。
  3. 开启 OneBot HTTP API 与 WebSocket 服务端，把两个端口映射到本机 127.0.0.1（下文以 HTTP 3000、WS 3001 为例）。

QQ 登录态保存在容器的数据卷里，删掉卷就要重新扫码登录。

3. DSH

安装 DSH 桌面版并启动 dsh web，记下它打印的端口。这个端口每次启动都可能变化；变了之后要同步修改 dsh.baseUrl，否则桥接连不上 DSH。

4. 获取并配置项目

git clone https://github.com/Derpyu520/qq-bridge.git
cd qq-bridge
npm install
cp config.example.json config.json
chmod 600 config.json

编辑 config.json，macOS 上需要特别注意以下几项：

键填什么
dsh.baseUrlhttp://127.0.0.1:<dsh web 的端口>，必须手填（见上文）
snowluma.wsUrl / httpUrl映射到本机的端口，例如 ws://127.0.0.1:3001 / http://127.0.0.1:3000
snowluma.accessTokenOneBot 的访问令牌，见下文
socialV2.voice.ffmpegPath启用语音时填 /opt/homebrew/bin/ffmpeg（或设置环境变量 FFMPEG_PATH）

OneBot 令牌从哪里来：桥接有两种拿令牌的方式。

  • 直接填写 snowluma.accessToken：令牌在 SnowLuma 的 OneBot 账号配置 config/onebot_<QQ号>.json 里。SnowLuma 跑在容器中时，这个文件在容器的数据卷里，需要自行取出。
  • 填 snowluma.homeDir：指向一个包含 config/onebot_*.json 的本机目录，桥接会自己扫描其中的令牌，换账号后也能跟上。容器部署时，这个目录需要能在本机看到（例如挂载出来）；如果是一次性拷贝出来的，SnowLuma 那边换了令牌，拷贝就会过期。

其余项（ownerQQ、allow.private / allow.groups 等）与 Windows 相同，见配置参考。

5. 安装 DSH 插件

node scripts/setup-dsh.mjs

脚本做了什么见安装步骤。DSH 根目录默认是 ~/.dsh，可用 DSH_HOME 覆盖。如果 dsh 命令不在 PATH 里，脚本会跳过插件依赖安装；之后需要手动执行 dsh plugin --profile web install。完成后重启 DSH。

6. 启动与停止

启动顺序：SnowLuma → DSH → 桥接。桥接连不上 DSH 时会直接退出。

npm start

想在后台运行，可以把输出重定向到日志：

nohup npm start > state/bridge.stdout.log 2>&1 &

桥接只允许一个实例。启动前先确认控制台端口没有被旧进程占用：

lsof -nP -iTCP:3100 -sTCP:LISTEN

停止：前台运行时按 Ctrl+C；后台运行时先确认 state/bridge.lock 里记的 PID 确实是本仓库的 node src/bridge.js，再 kill 它。restart.bat 和它调用的 scripts/stop-bridge-instance.mjs 只支持 Windows。

7. 验证

  1. 打开桥接控制台 http://127.0.0.1:3100，令牌在 state/console-token。
  2. 运行 npm run verify:adaptation 做一次自检，具体覆盖范围见验证是否装好。
  3. 在白名单会话里发一条消息测试收发；新装默认是二代仿真模式（reserved2），会选择性发言，测试时可先在控制台切到 chat。

常见问题

症状原因与处理
重启 DSH 后桥接连不上dsh web 端口变了，更新 dsh.baseUrl 或 DSH_WEB_URL
桥接提示已有实例在运行上一个桥接没有退干净，用 lsof 找到占用 3100 的进程
SnowLuma 连不上先确认 Docker 运行时与容器都在运行，再检查端口映射和令牌
日志时间差几个小时容器时区与本机不同，按各自时区对时间线
