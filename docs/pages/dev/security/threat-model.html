威胁模型

本文把项目里已经实现的安全边界、已知的残余风险、以及每次发布必须回归的 检查项集中到一处。与之配套的承诺性文档是 ../../RULES.md（面向使用者的 权限说明）；本文偏工程实现，供改动代码前后对照。

维护规则：任何改动如果改变了下面任一条目，必须在同一个 PR 里更新本文。

一、威胁模型（我们要防谁、防什么）

威胁主体能力假设我们不防的
QQ 群友 / 陌生人能给机器人发任意文本、图片、表情、拍一拍；能尝试提示注入他们能看到的公开信息
被注入的模型会尝试调用任意工具名、传任意参数、尝试外发本机内容——
本机其他用户能登录同一台机器，能读文件系统已取得管理员/root 的主体
本机其他进程 / 浏览器页面能访问 127.0.0.1，能构造任意 HTTP 请求已能读写本项目 state/ 的主体
DSH 侧 agent（QQ 会话）拥有 MCP 工具面，但没有本地工具——

不在此模型的范围内：QQ 账号本身被盗、SnowLuma 网关被攻陷、DSH 本体漏洞、 操作系统级攻击者。这些情况下本项目无法提供额外保护，README 中已声明。

三、已知残余风险（明确不修 / 修不了，必须让用户知道）

#风险现状与缓解为什么不修
R1敏感信息审计是启发式的能抓"带赋值关系的凭据"和本机路径；抓不到任意形态的秘密通用秘密检测无法在没有密钥的情况下做对；硬边界在白名单与工具面，审计是兜底
R2state/ 里的令牌是明文当前支持的 Windows 部署通过 ACL 收紧访问权限引入凭据库或 DPAPI 会增加部署与迁移复杂度；是否采用需结合本项目后续凭据保护设计评估
R3贴纸账号库仍共享，AI 备注仅保留一个归属版本私有认知已在 API、搜索和注入路径按 scope 隔离；其他会话更新认知会替换旧归属并清空旧私有字段QQ 收藏本来是全局资源；每会话多版本备注属于后续存储设计
R4远程停止不是原子的session/control + updateQueue + cancel 是尽力而为，已执行的工具副作用无法回滚DSH 协议没有事务语义
R5离线队列不保证送达每会话最多 50 条，进程退出即丢一致性代价过高；README 已写明
R6预设不变量检查是子串存在性防误删，不防恶意能改这个文件的人本来就是管理员，真正的硬边界在工具守卫与白名单
R7self-test.js 只证明链路通不做断言它是连通性探针，不是回归套件（回归在 npm run test:audit）
R8单人维护、无外部安全审计有离线回归 + 本文档内部审查不能替代独立的外部或对抗式安全评估
R9state/ 的 ACL 收紧可能失败（未提权且目录属主权限被策略收走时）scripts/harden-state-acl.mjs 会自动提权重试一次；仍失败则明确告警 + 给出可复制命令 + 控制台告警条改 ACL 属于需要特权的操作；降级为"明确告警"而不是"阻断启动"是刻意的取舍（否则用户会为了能启动而关掉整条安全链路）。其他凭据保护方案需在后续设计中单独评估，不能视为已经实现
R10收紧 state/ 后，DSH 沙箱会话写不进 state/（见 §2.6）有意取舍，非缺陷；诊断见 npm run diagnose:acl在当前 Windows 实现中，能力 SID 依赖继承下发，而切断继承是本项目阻止本机其他用户读取令牌的直接手段。代价已被接受并写进文档，项目自己的测试夹具/探针据此改用系统临时目录
R11plugins/** 内容被意外切断继承，沙箱里改不动 L7 守卫来源不明（本仓库无此脚本）；npm run diagnose:acl 会列出并打印恢复命令该处不含凭据，恢复继承无泄密风险；但若不恢复，被沙箱约束的 DSH agent 就无法维护工具守卫 —— 需要人工在无沙箱终端改
R12旧版本 AI 黑话可能已错误标成 global，或混入多群证据新写入与所有读取路径已按 scope 隔离，但现有 global 条目继续按全局语义可见；升级后需管理员复核、删除或重新指定归属错误保存时已丢失可靠归属，无法自动区分有意共享与历史污染，也不能可靠拆分混合解释
